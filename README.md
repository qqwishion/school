# Шаг

Рабочая библиотека учебных заданий для педагогов и родителей по ТЗ «TZ_Shag_v1», версия 1.0. Django, серверные шаблоны, CSS и небольшой JavaScript. В схеме нет детских аккаунтов и медицинских данных.

## Открыть на этом компьютере

Запустите **start.cmd** двойным щелчком или выполните в PowerShell:

```powershell
.\start.ps1
```

Откройте http://127.0.0.1:8000/materials/. Остановка приложения: Ctrl+C в окне запуска.

Для нового компьютера нужен Python 3.12–3.14 и доступ в интернет при первой установке. Скрипт создаёт `.venv`, устанавливает зависимости, применяет миграции и добавляет демонстрационные задания. Повторный `seed_demo` не перезаписывает редакторские изменения. Если окружение уже существует, зависимости можно обновить вручную: `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.

При отсутствии `DATABASE_URL` локальный режим использует SQLite. Для основной версии настройте PostgreSQL, как описано ниже. SQLite предусмотрен только для простого автономного запуска.

На текущем компьютере дополнительно подготовлен автономный PostgreSQL 17.11 в `.venv/postgresql/`, база `shag` на `127.0.0.1:55432`. `start.ps1` обнаруживает его и запускает автоматически. Системная служба не устанавливалась. Для административных команд сначала выполните `. ./scripts/portable-postgres.ps1` — это установит подключение и PATH в текущем PowerShell. В этом локальном кластере доверенная авторизация только на loopback; он предназначен для разработки, а не для сервера. Остановка: `& ./.venv/postgresql/pgsql/bin/pg_ctl.exe -D .venv/postgresql/data -m fast stop`. Бинарные файлы и данные не входят в исходный архив проекта.

## Что реализовано

- Каталог с поиском по названию, цели и ключевым словам без учёта регистра, включая кириллицу.
- Пять совместных фильтров: направление, возраст, сложность, формат, максимальное время. Условия объединяются через И.
- Три сортировки, 12 карточек на страницу, параметры в URL, возврат из материала с сохранением условий.
- Отдельные страницы материалов, текст задания, инструкция, изменение сложности, источник, сведения о проверке.
- PDF во встроенном просмотрщике, открытие и скачивание, печать страницы.
- Регистрация взрослого по имени, email и паролю; вход, POST-выход, уникальный email независимо от регистра, хешированные пароли.
- Избранное в базе, отдельное для каждого пользователя, POST и CSRF. Гостю предлагается войти с возвратом к материалу.
- Django Admin: редактура, вложения, проверка перед публикацией, снятие с публикации.
- Защищённая серверная выдача вложений и обложек: черновики доступны только сотрудникам, прямого `/media/` нет.
- Серверная проверка расширения и содержимого PDF/PPTX/PNG/JPEG, лимиты 20 МБ и 3 вложения.
- Мобильные фильтры, видимый клавиатурный фокус, ссылка к содержимому, состояния загрузки, ошибок и пустого поиска.
- Светлая и тёмная темы: при первом открытии учитывается системная настройка, ручной выбор сохраняется в браузере, синхронизируется между вкладками и применяется до загрузки стилей.
- Быстрые переключатели направлений сохраняют остальные фильтры и возвращают на первую страницу. Небольшие анимации карточек и декоративных элементов отключаются при `prefers-reduced-motion`.

## Демонстрационные данные и педагогическая проверка

`seed_demo` создаёт **18 оригинальных демонстрационных заданий**, по три на каждое из шести направлений, и **18 PDF** для печати. Тексты подготовлены с помощью ИИ; это явно указано в источнике.

У них статус `demo`, `reviewed=False`, пустые сведения о проверяющем. Они видны только при `DEMO_MODE=1`, с предупреждением в интерфейсе и PDF. Это отдельный режим сверх двух редакционных статусов ТЗ, позволяющий показать работу приложения без ложного утверждения о педагогической проверке. При `DEMO_MODE=0` эти записи не попадают в каталог и недоступны по прямым ссылкам посетителям.

**Для полного выполнения A14 необходима реальная проверка педагогом всех 18 заданий.** В админке педагог проверяет текст, вносит правки, указывает факт и сведения о проверке, затем публикует материал. Публикация без обязательных полей, источника, разрешения, задания/вложения и сведений о проверке отклоняется. PDF демонстрационного задания тоже следует заменить после проверки: команда seed намеренно не перезаписывает файлы и правки.

Уровни: «Начальный» — одно действие с наглядной опорой и помощью взрослого; «Базовый» — несколько действий и больше самостоятельности. Возраст — ориентир. Не публикуйте документы с персональными данными детей.

## Учётная запись администратора

Общего пароля и автоматически созданного администратора нет. Создайте личную запись:

```powershell
$env:DEBUG = '1'
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Админка: http://127.0.0.1:8000/admin/. Обычная регистрация создаёт только пользователя без прав редактирования. Восстановление пароля в пилоте выполняет администратор через карточку пользователя.

Сначала сохраните новый материал как черновик. Затем прикрепите файлы, проведите проверку и смените статус на «Опубликован». Для публикации без текстового задания сначала сохраните вложения в черновике. В массовых действиях доступны публикация с валидацией и снятие с публикации. Сохранённые пользователями ссылки на снятый материал временно скрываются; записи избранного сохраняются.

## PostgreSQL

Можно использовать установленный PostgreSQL или контейнер из `compose.yaml`:

```powershell
$env:POSTGRES_PASSWORD = 'задайте-свой-случайный-пароль'
docker compose up -d db
$env:DEBUG = '1'
$env:DEMO_MODE = '1'
$env:DATABASE_URL = 'postgresql://shag:URL-кодированный-пароль@127.0.0.1:5432/shag'
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Специальные символы в пароле в URL нужно закодировать. Настройки из `.env.example` являются образцом переменных окружения; Django не читает этот файл автоматически. Docker Compose самостоятельно поддерживает `.env` для переменных своего манифеста. SQLite и PostgreSQL — разные базы: после смены подключения примените миграции и наполнение заново.

## Проверки

```powershell
$env:DEBUG = '1'
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

Для тестов с PostgreSQL используемый пользователь должен иметь право создавать тестовую базу. Подробности выполненной проверки — в `VERIFICATION.md`.

Браузерный тест: установите Node.js и `npm install --prefix .venv/browser playwright`, затем `node scripts/browser-check.cjs` при запущенном приложении. На Windows используется установленный Edge; в других средах сначала установите Chromium командой `node .venv/browser/node_modules/playwright/cli.js install chromium`. Тест создаёт временного взрослого с email `browser-…@example.test`; удалите его из админки после проверки. Скриншоты сохраняются в `artifacts/`.

`node scripts/theme-check.cjs` дополнительно проверяет обе темы, сохранение выбора, системные настройки, клавиатурное переключение, заблокированный localStorage, работу без JavaScript, уменьшение движения и отсутствие переполнения на 360, 768 и 1440 px.

## Резервное копирование

Приостановите запись на время снимка, затем выполните:

```powershell
.\.venv\Scripts\python.exe manage.py backup
```

Создаётся каталог `backups/<время-UTC>/` с `database.sqlite3` или `database.dump` и `private_media.tar.gz`. Для PostgreSQL нужен `pg_dump` совместимой версии в PATH. Пароль передаётся процессу через окружение, не выводится. Храните резервные копии отдельно от приложения с ограничением доступа.

Восстановление SQLite: остановите приложение, сохраните текущую базу, замените `db.sqlite3` копией. Восстановите `private_media/` из архива в корень проекта. PostgreSQL: остановите запись, восстановите дамп командой `pg_restore --clean --if-exists --no-owner --dbname=shag database.dump` в подготовленную базу (параметры подключения через `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`), затем восстановите файлы. Сначала проверьте восстановление на отдельной базе. Секреты приложения сохраняйте отдельно.

## Развёртывание

Для сервера задайте `DEBUG=0`, `DEMO_MODE=0`, случайный `SECRET_KEY`, `DATABASE_URL`, домен в `ALLOWED_HOSTS` и HTTPS-origin в `CSRF_TRUSTED_ORIGINS`. Без собственного секрета и PostgreSQL production-режим не запускается. `DB_SSLMODE` задаёт SSL-режим соединения с базой; для удалённой базы настройте TLS согласно инфраструктуре.

Выполните миграции, `collectstatic`, создайте администратора и запустите WSGI:

```text
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check --deploy
waitress-serve --listen=127.0.0.1:8080 shag.wsgi:application
```

Перед WSGI нужен HTTPS reverse proxy с корректным TLS. Раздавайте `/static/` из `staticfiles/`, ограничьте размер тела запроса приблизительно 65 МБ. **Не раздавайте `private_media/` напрямую**: все файлы выдаются Django после проверки статуса. Reverse proxy обязан передавать корректную информацию о HTTPS; `SECURE_PROXY_SSL_HEADER` устанавливайте только при доверенном прокси, удаляющем подставленные клиентом заголовки. Альтернатива — TLS на WSGI-соединении. Закройте доступ к базе извне. Предусмотрите мониторинг ошибок и плановые резервные копии.

Готовый пример прокси — `deploy/nginx.conf.example`. Для этой конфигурации включите `TRUST_PROXY=1`: приложение доверяет `X-Forwarded-Proto`, который прокси принудительно перезаписывает. WSGI-порт должен оставаться доступен только самому прокси. PostgreSQL должен поддерживать ICU-коллацию `und-x-icu` для Unicode-поиска; она есть в проверенном EDB-кластере и стандартном образе PostgreSQL с ICU.

Для переносимости PDF на Linux установите `fonts-dejavu-core` или положите легально полученный `DejaVuSans.ttf` в `assets/`; Windows использует системный Arial. Персональные сведения не пишутся в прикладные логи. Публичное размещение в этой работе не выполнялось: ТЗ допускает локальный запуск для защиты.

## Файлы

- `shag/` — настройки и маршруты;
- `library/` — модели, формы, представления, админка, миграции и тесты;
- `templates/`, `static/` — интерфейс;
- `library/demo_data.py` — 18 текстовых заданий;
- `docs/TZ_Shag_v1.docx` — исходное ТЗ;
- `VERIFICATION.md` — результаты и границы проверки.

Выбор совместимой ветки Django проверен по [официальной документации Django 5.2](https://docs.djangoproject.com/en/5.2/releases/5.2/). Для Windows PostgreSQL доступны [официально распространяемые EDB бинарные архивы](https://www.enterprisedb.com/download-postgresql-binaries).
